# Java 17 + Maven, sibling directory `publication-exporter`, executable/artifact id `publication-exporter`

## 1. Problem Frame

**Signal:** S01 needs a concrete runtime, build tool, sibling directory name, and executable identity for &lt;new-exporter&gt; before any acceptance test can be wired; the plan forbids deciding this implicitly inside slice code.

**Constraints:**
- Must not collide with the exporter-java directory, which remains a compatibility oracle, not a code donor.
- Must be easy to compare/cross-check against exporter-java's Java/Maven toolchain.
- Naming should use existing project domain vocabulary (publication, not a version-numbered 'v2'/'next' name that rots).
- OS-level packaging/distribution strategy is explicitly out of scope here — deferred to G5.

**Acceptance:** A recorded decision states the runtime/language, build tool, sibling directory name, and executable/artifact name for the new exporter, consistent with the operator's Java/Maven choice.

## 2. Decision

**Selected:** Java 17 + Maven, sibling directory `publication-exporter`, executable/artifact id `publication-exporter`

**Selection policy:** Operator directive: Java/Maven, confirmed explicitly in conversation. Directory and executable naming derive mechanically from that plus the constraint of not colliding with exporter-java.

**Why selected:** Java 17 matches applying-sbpp's supported target (Java 17+/Kotlin 1.9+) and exporter-java's own runtime, keeping the compatibility-oracle comparison direct. Maven matches exporter-java's build tool, per operator instruction. `publication-exporter` uses the project's own domain vocabulary (the BoundedContext is PersonalSite_Publication) instead of a version-numbered name, sits as a new sibling next to exporter-java/obsidian-plugin/site, and doubles as both the Maven artifactId and the CLI invocation name referenced by future bridge-client wiring.


**Invariants:**
- The new sibling directory is named `publication-exporter` and never collides with `exporter-java`.
- exporter-java remains unmodified as an evidence source and compatibility oracle.

**Pre-conditions:**
- [ ] None — this is the first decision for the new project.

**Post-conditions:**
- [ ] A `publication-exporter/` directory with a Maven pom.xml (Java 17) exists as the build root for all S01+ work.
- [ ] The CLI/artifact identity `publication-exporter` is used consistently in build config, docs, and later bridge-client wiring.

**Admissibility:**
- NOT: No code is copied from exporter-java into publication-exporter; it is evidence only.

## 3. Rationale

**Counterargument:** A more generic name like `exporter2` or `exporter-next` would be shorter, but rots in meaning once there's a third attempt or once exporter-java is eventually retired; `publication-exporter` stays descriptive regardless of ordinal history.

**Selected variant weakest link:** OS-level executable packaging (shaded jar + launcher script vs. native-image) is not decided here and is deferred to G5; until G5, `publication-exporter` names the artifact/CLI identity, not a concrete spawn-able binary path.

**Rejected alternatives:**
| Variant | Verdict | Reason |
|---------|---------|--------|
| Java 17 + Maven, sibling directory `publication-exporter`, executable/artifact id `publication-exporter` | **Selected** | Java 17 matches applying-sbpp's supported target (Java 17... |
| Kotlin/Gradle | Rejected | Operator explicitly chose Java/Maven. |
| TypeScript/Node | Rejected | Operator explicitly chose Java/Maven; would also lose direct JVM comparability with exporter-java. |
| Reuse/rename exporter-java in place | Rejected | Plan requires exporter-java to remain untouched as an evidence source and compatibility oracle, not be overwritten. |

**Evidence requirements:**
- `publication-exporter/pom.xml` builds successfully on Java 17.

**Predictions:**
| Claim | Observable | Threshold |
|-------|------------|-----------|
| The Maven/Java 17 toolchain requires no exotic setup beyond what exporter-java already uses in this environment | `mvn -q -f publication-exporter/pom.xml validate` (or equivalent) exit code | == 0 |

## 4. Consequences

**Rollback plan:**
Triggers:
- Java/Maven proves unworkable for a reason not currently foreseen
Steps:
1. Delete the `publication-exporter/` directory before any approved/release state exists
2. Re-open this gate decision with the new constraint recorded
Blast radius: Pre-S01, so nothing durable depends on the directory yet.

**Refresh triggers:**
- G5 (distribution) is decided — revisit whether the executable identity needs to change for packaging
- The operator asks to rename or relocate the new project
