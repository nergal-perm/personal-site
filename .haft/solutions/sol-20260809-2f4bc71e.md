# Distribution options for G5 macOS-native delivery

Problem: prob-20260809-7d4a1e6c

## Variants

### V1-macos-arm64-native. macOS Apple-Silicon GraalVM native executable

Build and distribute one GraalVM native executable for macOS Apple Silicon. The operator places it at a stable local path and configures that absolute path in the Obsidian plugin. The native executable is the supported runtime; Maven/JVM execution remains a development and diagnostic route.

**Strengths:** matches the successful real-plugin/native pilot and needs no Java runtime at the publishing point.

**Weakest link:** a future need for Intel macOS, code signing/notarization, or managed update/install requires a fresh distribution decision.

### V2-macos-jvm-launch. macOS JVM/JAR launcher as the supported runtime

Publish a launcher that runs the exporter JAR under a locally installed Java runtime.

**Strengths:** avoids native-image reflection metadata and makes debugging straightforward.

**Weakest link:** shifts Java runtime/version setup to the publishing operator and conflicts with the now-demonstrated native executable path.

### V3-multi-platform-native. Multi-platform native releases

Build and support native executables for macOS, Windows, and Linux.

**Strengths:** broader portability if the exporter becomes a multi-user product.

**Weakest link:** introduces cross-platform build, support, and release obligations before any such operator exists; it directly contradicts the explicit no-Windows/no-Linux constraint.

## Comparison

**Selection policy:** choose the smallest distribution contract that is proven by the real-plugin pilot, minimizes operator prerequisites, and makes no unsupported-platform promise.

| Variant | Proven in current operator context | Operator prerequisites | Scope fit |
| --- | --- | --- | --- |
| V1 macOS Apple-Silicon GraalVM native executable | Yes | configured binary path | Selected |
| V2 macOS JVM/JAR launcher | JVM run only | Java runtime plus launcher | Rejected |
| V3 multi-platform native releases | No | platform-specific packaging/support | Rejected |

## Recommendation

**V1-macos-arm64-native. macOS Apple-Silicon GraalVM native executable**

The only option demonstrated by the pilot that keeps Java setup out of the operator path and preserves the explicit scope boundary.
