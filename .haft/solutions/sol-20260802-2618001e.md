# Solutions for: Wire up the real semantic link resolver end-to-end

Problem: prob-20260802-1803dd18

## Variants (2)

### V1. Publication-frontier Zettelkasten identity (base)

Use the vault source id as durable semantic identity and publicId only as route slug. Before Prepare may proceed, the exporter authoritatively requires a valid stable unique immutable ID on the current page and every uniquely resolved direct private target; it forbids path fallback, constructs route-independent targetRef from the source ID, and keeps the catalog/index rebuildable. The existing Obsidian command remains a thin note-path bridge with no graph preflight.

**Strengths:**
- Authoritative identity survives rename and catalog loss
- No central identity allocation race
- Same CLI, fixture, and Obsidian semantic path
- No MetadataCache dependency

**Novelty:** The base control isolates the value of source-owned identity and explicit frontier admission without importing any graph-derived operator experience.

**Weakest link:** The exporter can block with an actionable missing/duplicate-ID list only after Prepare begins, and it offers no immediate current-vault backlink preview; the operator learns graph hygiene and potential activation impact later and through a narrower interface.

**Risks:**
- Global/frontier uniqueness and immutability enforcement still need a precise lock/revalidation design
- A missing target ID consumes a Prepare attempt before the operator sees the complete repair list
- No current-vault backlink impact preview

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** The identity model remains the required semantic core beneath any later advisory graph UI.

**Diversity role:** control: source-owned identity only

**Rollback:** Begin with fixture-only admission validation; no automatic source-note or approved-snapshot rewrite.

### V2. Publication-frontier Zettelkasten identity with Frontier Lens

Keep the base source-ID and exporter-authority model unchanged, but precede the existing Obsidian Prepare call with a read-only Frontier Lens. The plugin uses MetadataCache cached links, resolved/unresolved link maps, and an inverse backlink view to show the current page, its direct target candidates, cached ID problems, and potential current-vault referrers. It maintains an in-memory cache epoch from metadata and vault create/delete/rename events; null caches, churn, or disagreement display stale/incomplete rather than clean. Continue invokes exactly the existing prepare(notePath) bridge; no graph payload, targetRef, ID, route, or backlink enters the exporter request, candidate, approved triple, translation job, or public output. The exporter independently re-reads source/target bytes and remains authoritative for membership, identity admission, ambiguity, occurrence order, atomic approval, and actual activation impact from approved reference maps.

**Strengths:**
- Finds missing/copied IDs before costly translation
- Shows potential referrers without touching them
- No new trusted bridge payload or approval surface
- Cache failure degrades to uncertainty while authoritative Prepare still works
- Preserves native CLI and fixture behavior

**Novelty:** Extracts V4's graph as a zero-authority operator lens instead of a second semantic input: it gives early hygiene and impact feedback while contract-freezing the exporter and preserving CLI/fixture equivalence.

**Weakest link:** MetadataCache can lag edits and current-vault backlinks cannot prove immutable approved-map occurrences; duplicated preview rules may drift, so the UI must label results potential/incomplete and never treat a green preview as publication admission.

**Risks:**
- Plugin-side ID/link preview rules can drift from exporter rules
- Warm-cache whole-vault ID preview may add latency
- A polished green state may be mistaken for approval
- Obsidian API/cache timing changes can stale the lens
- Private paths and IDs must remain local and unlogged

**Stepping stone:** yes — opens future possibilities

**Stepping-stone basis:** Measured preview/exporter disagreement and latency can later justify a source-hash-bound advisory envelope without changing source identity or approval semantics.

**Diversity role:** augmentation: zero-authority graph preflight and impact lens

**Rollback:** The lens is a read-only preflight in the plugin; disabling/removing it restores the exact base Prepare call and leaves no durable state to migrate.
