# Translation-engine selection options

Problem: prob-20260809-e3a75c4b

## Variants

### V1-root-file-env-override. Exporter-root TOML with environment override

Read `[translation].engine` from `publication-exporter.toml` in the process
working directory; a non-blank `PUBLICATION_EXPORTER_TRANSLATION_ENGINE`
temporarily overrides it. Select a concrete Codex or Antigravity command using
the existing `TranslationCommand` seam.

**Strengths:** persistent setting works for the Obsidian GUI launch because the
plugin already supplies the exporter root as `cwd`; the environment override is
useful for diagnostics without editing a file; no bridge or plugin change.

**Weakest link:** direct CLI users must run in their intended exporter root;
new engine names require an intentional code release rather than an arbitrary
command template.

### V2-environment-only. Environment variable only

Select the engine only from `PUBLICATION_EXPORTER_TRANSLATION_ENGINE`.

**Strengths:** no parser or local file to manage.

**Weakest link:** GUI-launched applications have an unreliable and opaque
environment, so the operator cannot see or persist the active editorial
engine alongside the review and job directories.

### V3-plugin-setting. Obsidian plugin engine setting

Add an engine selector to the plugin and pass it to the exporter.

**Strengths:** visible inside Obsidian settings.

**Weakest link:** turns an exporter-owned worker concern into a bridge/plugin
contract, requiring plugin deployment for a backend-only switch and violating
the no-new-CLI-argument constraint.

## Comparison

**Selection policy:** prefer the smallest operator-visible configuration that
works under the current Obsidian process model, preserves the existing worker
boundary, and permits a temporary override without changing bridge arguments.

| Variant | Persistent GUI-safe choice | Temporary switch | New bridge/plugin surface |
| --- | --- | --- | --- |
| V1 root TOML + environment override | Yes | Yes | No |
| V2 environment only | No | Yes | No |
| V3 plugin setting | Yes | No | Yes |

## Recommendation

**V1-root-file-env-override. Exporter-root TOML with environment override.**

It is the only option that maintains a clear persistent operator choice while
remaining inside the already-proven process configuration boundary.
