# S15 final whole-branch review caught missing GraalVM reflect-config entries for new command/DTOs — fixed

## Observations

- The S15 tasks.md plan (write-publication-contract command, ADM-06) never mentioned publication-exporter/src/main/resources/META-INF/native-image/reflect-config.json, so none of Tasks 1-4 registered the four new classes (WritePublicationContractCommand, PublicationContract, KindContract, FieldContract) there.
- Per dec-20260809-5a8f3d2c (GraalVM native executable is the sole supported distribution), an unregistered class breaks reflective instantiation/serialization in the native binary even though the JVM-based Maven test suite stays fully green — this gap was invisible to all four per-task reviews and would have shipped undetected without the final whole-branch review.
- Fixed in commit 00fde10: five new reflect-config.json entries (the four classes plus FieldContract's nested Type enum), verified against the real @JsonProperty accessor names in source and re-reviewed as ADDRESSED with no new breakage.
- Process lesson for future slices: any tasks.md that adds a new CLI command class or a new Jackson-serialized DTO in publication-exporter should include a reflect-config.json registration step directly in the plan, not rely on catching it at the final review.

## Rationale

This is exactly the class of cross-cutting gap the final whole-branch review exists to catch (per the standing S03 precedent) — worth recording both the specific fix and the generalizable planning lesson so future tasks.md authoring accounts for GraalVM registration up front.
