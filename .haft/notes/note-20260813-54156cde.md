# G7 decision's about-page JSON artifact prediction narrowed: drop topics/links/sourceHash/sourceLanguage/translationStatus

## Observations

- site/src/data/pages/ru/about.json (the real, currently-shipping legacy-produced fixture) does carry the five dropped fields, but that is the legacy exporter-java's own output shape, not a requirement any current publication-exporter kind's contract or FilesystemManagedSiteInstaller output matches.
- openspec/changes/s17f-editorial-curated-page-kind/specs/public-content-model/spec.md's PCM-02 scenario and tasks.md's CuratedPageJson.render already reflect the narrowed field set consistently.

## Rationale

Carrying those five fields into editorial/curated_page's JSON artifact for legacy parity alone would be scope creep unsupported by any evidence from the six kinds already implemented in this exporter edition, and would violate the project's own minimal-slice discipline. The corrected, narrower field set (id, type, language, title, summary, eyebrow, lead, principles, colophon, searchable) is what site/src/lib/registry.ts's fromPage() actually consumes, and is now what openspec/changes/s17f-editorial-curated-page-kind/specs/public-content-model/spec.md and design.md both specify. The G7 decision itself (freeze the nine-page grammar as one edition, implement only about this slice) still holds; only this one predicted detail is corrected.
