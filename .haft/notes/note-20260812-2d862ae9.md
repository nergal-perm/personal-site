# S17d Task 4 dismissed findings: acceptance-test scope matches established one-fixture precedent, not CLI-process-level

## Observations

- Dismissed (Important) - reviewer flagged ConceptAcceptanceTest for using in-memory handler wiring instead of 'the real CLI'. Verified: BibliographyBookAcceptanceTest, BlogClaimAcceptanceTest, and BlogNoteAcceptanceTest -- the explicit sibling models named in this task's own brief -- are ALL structured identically (real PrepareHandler/MarkReviewedHandler/BuildFromReviewHandler/FilesystemManagedSiteInstaller objects wired with Null* fakes, not a CLI process invocation). The task brief's phrase 'via the real CLI' was the controller's own imprecise wording during planning; the actual established, already-shipped convention is handler-level acceptance testing. CLI process/argv concerns are covered separately and generically by the *CliAcceptanceTest family (PrepareCliAcceptanceTest, BuildFromReviewCliAcceptanceTest, etc.), not duplicated per content kind.
- Dismissed (Critical) - reviewer flagged ConceptAcceptanceTest for covering only one populated valid fixture, missing co-admission/absent-fields/malformed-blocked/EN-misalignment scenario coverage. Verified: every existing sibling acceptance test file (BibliographyBookAcceptanceTest, BlogClaimAcceptanceTest, BlogNoteAcceptanceTest) has exactly ONE @Test method (grep count confirmed). This matches openspec/implementation-plan.md's own explicit S17a-S17f acceptance criterion: 'one fixture of the new kind can complete the already-working prepare -> approve -> release path'. Malformed/blocked-field coverage is Task 2's ConceptPublicationKindTest's job (already reviewed and shipped); EN structural-alignment coverage is the shared, kind-agnostic EnglishCandidateValidatorTest's job -- the spec.md scenarios this slice itself wrote explicitly state 'using the same structural-alignment rule already proven for blog/essay, with no concept-specific exception', i.e. deliberately NOT re-proven per kind in the acceptance test.

## Rationale

Both findings, if acted on, would have made ConceptAcceptanceTest diverge from every already-shipped sibling kind's acceptance test shape and duplicated coverage the project's own design already places elsewhere on purpose. Dismissed with ruling rather than looped, per this project's established practice of parking well-evidenced false positives.
