# S17d Task 3 parked minor: BracketIndexedFields scalar-then-lists ordering is not general interleaving-preserving

## Observations

- Spec-compliance review: BracketIndexedFields.render() writes every scalar field immediately via callback during iteration, but accumulates list-shaped fields and appends their blocks only after the full iteration completes (via the method's return value). The final rendered order is always [all scalars, in original order] then [all list blocks, in order of first appearance] -- not a strict preservation of arbitrary scalar/list interleaving in the source PublicField list.
- Not a defect for this slice: ConceptPublicationKind's own field order already places title/description/notThis (scalars) before relations/examples (lists), so the final frontmatter output matches the intended order exactly.
- Would become a real latent bug only if a future kind interleaves scalar and list-shaped fields in a different order (e.g. scalar, list, scalar) and depended on that exact interleaving surviving into installed YAML -- no such kind exists yet.

## Rationale

Real but non-load-bearing for this slice; flagged so a future kind adopting the bracket-index convention with interleaved field ordering re-checks this assumption before relying on it.
