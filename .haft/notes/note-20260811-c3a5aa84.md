# S15 write-publication-contract deliberately avoids BridgeResponse — new standalone PublicationContract type

## Observations

- S15's functional collaborative-design pass considered routing write-publication-contract's response through the existing schema-v2 BridgeResponse envelope, then rejected it.
- The contract response (contractVersion, kinds[] with required-field/allowed-value/structured-body descriptions) is a static declarative document, not an operation outcome — it has no ok/status/diagnostics/identity/candidateState-shaped fields to populate.
- Forcing it through BridgeResponse would have added a 16th nullable field to the exact class prob-20260808-08cf74cd already flags as an overgrown multi-shape DTO (15-parameter constructor, shape selected by which parameters are null).
- Decision (operator-confirmed): write-publication-contract emits its own standalone PublicationContract JSON document, outside BridgeResponse and outside bridge-contract/schema-v2.json's conformance surface.

## Rationale

Keeps a semantically unrelated response shape out of BridgeResponse instead of compounding the wide-DTO problem already under Haft review; this does not resolve prob-20260808-08cf74cd (which is about BridgeResponse's existing command responses), it only avoids adding a new case to the same pattern.
