# EnglishCandidateValidator's asset-route-preservation check is bypassable by deliberately adversarial translation-worker output (IPv6-literal and schemeless protocol-relative URLs)

## Observations

- ASSET_REFERENCE's negative-lookbehind-plus-external-URL-stripping defense (EnglishCandidateValidator.java, commits 5bd37ff, 7ebb334, 8a43e32) closes domain-substitution, Unicode-domain-substitution, and scheme-prefixed-fragment bypasses.
- S14's final whole-branch review (round 3, gpt-5.6-sol) found two more bypasses that survive: (1) an IPv6-literal host URL like 'https://[2001:db8::1]/assets/vault/{hash}.ext' exploits EXTERNAL_URL's own '[^\s)\]]+' character class (which excludes ']' to avoid consuming a markdown '[label]' closer), causing EXTERNAL_URL to under-match and stop before the ']', leaving '/assets/vault/{hash}.ext' unstripped and still substring-matchable; (2) a schemeless protocol-relative URL with '#' immediately before the route, e.g. '//cdn.example/#/assets/vault/{hash}.ext', is caught by neither defense (no http(s):// scheme for EXTERNAL_URL to strip; '#' was never added to the lookbehind's excluded-character set).
- Both bypasses require the TRANSLATION WORKER's output to contain one of these specific crafted URL shapes wrapping the exact local route substring — not an accidental translation mistake, but a deliberately adversarial output.
- A fully robust fix requires parsing actual Markdown link destinations (extract every (label, destination) pair from ru/enBody, compare destination sets directly) rather than regex substring-diffing, which is a materially larger scope change than incremental character-class patching.
- Operator decision (2026-08-11): park this as documented residual risk and archive S14 as-is, since the realistic threat model (translation worker accidentally dropping/mangling a reference) is well-covered by the current fix, and the remaining gap requires adversarial output from a trusted, project-configured translation engine — not a realistic scenario for this project today.

## Rationale

Recorded so a future decision can weigh whether to invest in the larger link-destination-parsing rewrite (e.g. if the translation worker is ever swapped for one with a weaker trust boundary, or if this check's threat model changes) rather than losing this finding once the S14 OpenSpec change archives.
