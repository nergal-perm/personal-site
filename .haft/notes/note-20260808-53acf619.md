# ReferenceMapCodec.read() throws uncaught NullPointerException on well-formed-but-incomplete JSON

## Observations

- S11's final whole-branch review (Codex gpt-5.6-sol xhigh) found that ReferenceMapCodec.read() calls .get(fieldName).asText() for required fields (ruHash, enHash, publicationIdentity's nested fields, etc.) without null-checking JsonNode#get's result. A syntactically valid JSON references.json missing an expected field (e.g. literal {}) returns null from .get(...), and .asText() on null throws NullPointerException.
- This is pre-existing, predates S11, and is reachable from any FilesystemCandidateWorkspace.read()/FilesystemApprovedSnapshotWorkspace.read() call — meaning inspect-publication and prepare are also exposed to this uncaught NPE on a malformed candidate/approved manifest, not just S11's new refresh-publication-queue command.
- S11 commit 8662093 worked around this DEFENSIVELY, not at the root: RefreshPublicationQueueHandler.reconcileOne() now catches RuntimeException (broadened from the narrower I/O/confinement/state exception types) around the candidate/approved lookups specifically, so refresh's own per-note loop no longer aborts entirely on this NPE — but inspect-publication and prepare still have no such catch and would still crash uncaught if they ever hit this exact malformed-JSON scenario.
- Root fix (not done): add null-checks in ReferenceMapCodec.read()'s field extraction, throwing a proper checked/typed parse-failure exception (matching the ApprovedSnapshotIntegrityException/CandidateWorkspaceConfinementException family's pattern already established elsewhere) instead of letting a raw NullPointerException escape. This benefits every caller uniformly, not just refresh.

## Rationale

Genuine, confirmed correctness gap in shared pre-existing code, out of scope for S11's minimal-slice discipline to root-fix (touching ReferenceMapCodec broadly is a cross-cutting change affecting inspect/prepare/mark-reviewed/build-from-review, not a one-slice concern) but worth flagging for prioritization since it's a real uncaught-crash risk, not just a style nit.
