# RefreshPublicationQueueHandler's UNCHANGED shortcut skips the hash guard within a narrow admission-to-decision window

## Observations

- S11's final whole-branch review (Codex gpt-5.6-sol xhigh) found that when reconcileOne's classified status already equals the persisted workflowStatus, it returns UNCHANGED immediately without any hash-guard verification against the current file state — unlike the UPDATED path, which always goes through WorkflowStatusEditor's guarded write. If the note changes in the narrow window between NoteIntake.admit()'s read and this UNCHANGED decision (a few in-memory workspace lookups, no I/O sleep), the reported UNCHANGED could reference already-stale data.
- Explicitly deferred (not fixed) by the operator-directed fix wave (commits f7ce96e, 8662093): fixing it cleanly would require either extending the WorkflowStatusEditor port with a read-only verify-current-hash operation, or writing back byte-identical content just to exercise the guard (which would needlessly perturb file mtimes/metadata for a no-op write).
- This is a much narrower race than the findings that WERE fixed (a few in-memory calls vs. e.g. PrepareHandler's translation-duration window) and closer in kind to other already-accepted operational-assumption races in this codebase (e.g. BRG-06's documented 'not invoked mid-translation' assumption in scope-pins.md).

## Rationale

Explicitly deferred by operator direction during the final review's fix-wave dispatch; recorded so the reasoning and scope boundary survive S11's archival.
