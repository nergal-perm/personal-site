# S17d Task 1 parked minor findings: FieldContract STRUCTURED_LIST naming/test-assertion nits

## Observations

- Code-quality review: FieldContractTest.equalStructuredListContractsMatchOnNameTypeAndMembersOnly asserts unequal objects must have unequal hashCode(), which Java's contract does not require (only equal objects must share a hash code); a valid future implementation could collide and fail this test despite being correct.
- OO-design/SBPP review: FieldContract.nonBlankStructuredList's name implies the list itself must be non-blank, but the factory sets nonBlank=false (only the member values are validated as non-blank elsewhere) - the name is slightly misleading about what it guarantees.
- SBPP review: the structuredMembers field/accessor name doesn't reveal that it holds required member-field *names* (a schema), not member values.
- SBPP review: local variable names in PublicationContractConformanceTest.structuredListFieldSatisfied (values, value, member) don't identify their roles as structured-entry-list, one-entry, and required-member-name.
- Spec-compliance review: fieldSatisfied's existing STRING branch was refactored to handle a null string.string() value, which is unrelated scope creep beyond Task 1's brief (harmless, but technically outside the task's stated boundary).

## Rationale

Deferred per the SDD process's Minor-findings rule (never enter the fix loop; recorded so the OpenSpec change folder's eventual archival doesn't lose the record). None are load-bearing for Task 2 or later slices.
