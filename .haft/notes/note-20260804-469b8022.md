# EssayAdmission source-identity frontmatter key renamed sourceId → id

## Observations

- S02 (archived) had EssayAdmission read the note's stable source identity from a frontmatter key literally named `sourceId`.
- The operator's real Obsidian vault already has many notes carrying a frontmatter key named `id` holding Zettelkasten-style values — the exact stable, human-assigned identity SEM-01 requires.
- The literal string `sourceId` was not referenced anywhere outside publication-exporter's own admission code and tests — not in bridge-contract/schema-v2.json, obsidian-plugin/, or openspec/requirements-baseline.md — so renaming it carried no external contract cost.
- The frontmatter key was renamed to `id` in EssayAdmission.java (and its own tests, plus the InspectPublicationHandler/CLI/SchemaConformance tests that construct essay fixtures), landed as its own small commit ahead of S03's prepare work. The internal Java identifier/method name `sourceId` (EssayAdmission.Result#sourceId()) was kept unchanged — only the frontmatter key string and the reported diagnostic field name changed, to avoid confusion with `publicId`.
- All 84 existing tests pass unchanged in behavior after the rename; FrontmatterTest's own `sourceId` fixtures were left as-is since that test exercises generic key/value parsing and doesn't encode EssayAdmission's real-world key choice.

## Rationale

Reusing the vault's existing `id` field means real notes satisfy SEM-01's identity requirement without the operator having to backfill a second field on every note. This was cheap to do now (greenfield, no external consumer of the key name) and would only get more expensive the longer S03+ built on top of `sourceId`.
