# S17e — music/album kind and second translated-list use case (ADM-03, ADM-04, PCM-02, PCM-06)

## Signal

Whole-vault admission and the publication contract cannot cover music/album; no album note can travel through prepare -> approve -> release -> site install, and write-publication-contract omits the kind entirely, even though the live site already serves one real album fixture with real translated and invariant content.

## Problem Profile

thin

## P2W Readiness

p2w_blocked

## Scope

publication-exporter/src/main/java/dev/eugene/publicationexporter/{admission,contract,reference,prepare,translation,site}/ and matching test packages. No changes to exporter-java/ (evidence-only) or to site/ (already-shipped schema/views, evidence-only for this slice).

## Acceptance

One music/album fixture completes admit -> prepare -> approve -> build-from-review -> install-to-site through the real CLI, matching the S17a-S17d slice shape. write-publication-contract includes the music/album kind with deterministic field ordering. The translated-vs-invariant posture of every album field (artist, work, format, context, association, care, listenFor, genreTags, releaseDate, streamingUrl, bandcampEmbedUrl, reviewType) is explicitly decided against real evidence (the live fixture pair), not guessed. The decision on whether to extract a shared translated-list mechanism now that a second kind needs it is made explicitly, not silently repeated or silently generalized. Existing blog/bibliography/concepts kind acceptance suites remain green; mvn -f publication-exporter/pom.xml test passes.

## Blast Radius

One new PublicationKind implementation, reuse or bounded extension of S17d's translated-list flattening/BracketIndexedFields mechanism, and a new invariant-list carrier for genreTags (matching book's authors precedent). No irreversible migration or external state change; plain git revert rolls back.

## Reversibility

reversible
