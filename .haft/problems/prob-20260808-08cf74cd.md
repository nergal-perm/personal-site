# BridgeResponse has grown into a wide multi-shape DTO — decompose or keep?

## Signal

BridgeResponse (publication-exporter/src/main/java/dev/eugene/publicationexporter/bridge/BridgeResponse.java) started as a small schema-v2 value type (2b7b744) and has been additively widened by every command that needed a new response shape since: essayInspected's 4 state fields (6bc38a4), reviewPlan (c17db77), and now (S11 Task 8, 78e29d4) queueRefreshed's 3 count fields. It is now one class with a 15-parameter positional constructor, where every factory method selects its response shape by which subset of parameters it passes as null. A Codex oo-design-heuristics review of S11 Task 8 flagged this as an Important Riel 2.3/2.6/2.8 violation (one class modeling several unrelated response-shape abstractions; positional-null construction that silently selects a shape). Tasks.md's own Task 8 text explicitly mandated extending the pattern this way, so the review finding conflicts with the plan text rather than a coding mistake — the operator chose to defer the design question rather than override the plan mid-slice.

## Constraints

- Must not break bridge-contract/schema-v2.json wire compatibility or any existing SchemaConformanceTest case.
- Any migration must not touch obsidian-plugin/ consumption contracts without a separate, explicit decision.
- Does not block or gate completion of S11 (openspec/changes/s11-refresh-publication-queue) — S11 proceeds with the current wide-DTO pattern as planned.

## Acceptance

A decision is recorded on whether to (a) keep the single wide-DTO-with-nullable-fields pattern as this project's deliberate, intentional convention for BridgeResponse (closing this problem as addressed-by-affirmation), or (b) decompose BridgeResponse into a small common envelope plus typed per-command payload variants, with a scoped follow-up slice/task to carry out the migration without breaking bridge-contract/schema-v2.json conformance.

## Blast Radius

publication-exporter's bridge package and every command handler that constructs a BridgeResponse (inspect, prepare, mark-reviewed, build-from-review, install-to-site, refresh-publication-queue) plus bridge-contract/schema-v2.json and its conformance tests.
