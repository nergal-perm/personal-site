# S03 — Prepare the first essay candidate

## Signal

S02 (closed, prob-20260804-60dfda6c) made `inspect-publication` report real identity and four independently-absent state dimensions for a valid `blog/essay`, but every one of those dimensions is hard-coded absent — there is still no command that produces a candidate. Per openspec/implementation-plan.md's S03 entry, the exporter needs a `prepare` command that, for the S02 essay, creates exactly one coherent first-publication candidate triple (normalized RU, worker-produced EN, and an empty valid references.json) and returns schema-v2 `ready_for_review`, without touching approved or site state. This is also where two plan-level decision gates land: G3 (production translation worker protocol, cancellation, timeout, result carrier — tests must stay worker-neutral) and G4 (semantic/site-acceptance vs byte-for-byte legacy compatibility depth for the RU normalization this slice performs) are both listed as required 'before S03' and are not yet decided (haft_query status shows no G3/G4 decision).

## Constraints

- Introduces at most one new production boundary adapter per the plan's slice discipline (condition 4); if the acceptance boundary genuinely needs both a worker adapter and a candidate-workspace adapter, that tension must be resolved explicitly in design.md, not silently.
- No candidate replacement, incremental diff (TRP-02/03), job isolation (TRP-04), semantic occurrence IDs (TRP-05/SEM-02), links/assets/protected-Markdown (PCM-03/04/05, S12-S14), or concurrent-job handling in this slice — those fail closed as unsupported state.
- exporter-java remains a read-only compatibility oracle (evidence), never a code donor.
- Governed by /nullables, /applying-sbpp, and /oo-design-guide for all new code, per the standing project convention (memory feedback-exporter-design-testing-conventions).
- Outside-in TDD discipline per implementation-plan.md: failing acceptance test first, in-memory fakes before real adapters, unit tests only for genuinely combinatorial logic.

## Acceptance

`publication-exporter prepare --json` for the S02-admitted valid essay creates one candidate workspace holding RU (normalized source), worker-produced EN, and an empty valid `references.json`, and returns a schema-v2 response with `ok: true`, `status: "ready_for_review"`; approved-snapshot and release/site state are provably untouched. Preparing an unrelated invalid publication does not create a job or candidate for it (ADM-05). The essay's manifest entry carries only PCM-01/PCM-02-projected fields for this slice's scope. G3 and G4 are each closed with a recorded Haft decision before design.md is finalized. All new acceptance/unit tests plus the full existing 84-test publication-exporter suite stay green; the in-memory acceptance subset stays under 1 second per the plan's slice discipline.

## Blast Radius

publication-exporter/ (new prepare command, candidate workspace adapter, translation worker port + real adapter); openspec/specs/{translation-preparation,public-content-model,semantic-references,publication-admission,workflow-bridge}/ (delta specs); obsidian-plugin/ conformance fixtures (test-only, new ready_for_review response shape). No change to exporter-java, vault content, approved/release state, or the Astro site.
