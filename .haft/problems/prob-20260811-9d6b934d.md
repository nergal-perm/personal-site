# S15 — Machine-readable publication contract (ADM-06)

## Signal

EssayAdmission (publication-exporter/src/main/java/dev/eugene/publicationexporter/admission/EssayAdmission.java) hardcodes the only content kind's admission rules (publish=true, publicCollection="blog", publicContentType="essay", slug-shaped publicId, non-blank id/title/description) as Java conditionals with no externally readable description. Authoring tools (the Obsidian plugin, editors) have no deterministic, machine-readable statement of what fields are required, what values are allowed, and what a valid publication body looks like for the kinds this exporter edition currently implements. There is also no harness proving that a published contract and the exporter's own runtime validation logic (EssayAdmission today) agree — the two could silently drift.

## Constraints

- One command response plus one shared fixture table — no new production adapter
- Do not generate internal OOP design (class shapes) from the external contract; the contract is a projection of admission rules, not their source
- No whole-vault discovery in this slice
- No new content kind introduced in this slice
- In-memory/CLI acceptance subset stays well under the 1s slice budget

## Optimization Targets

- Contract/validator agreement (zero drift between published contract and EssayAdmission behaviour)
- Deterministic byte-equivalent contract output across repeated requests

## Acceptance

A new `write-publication-contract` command emits a deterministic, schema-described contract for every content kind implemented so far (currently blog/essay only). Requesting the contract twice for the same exporter edition with no contract changes yields byte-equivalent output after declared serialization normalization. A shared fixture table drives both runtime admission validation and a contract-conformance harness; any fixture the published contract accepts but runtime validation rejects (or the reverse) fails the exporter edition's acceptance suite. Discovering notes across the vault and adding any new content kind remain explicitly out of scope.

## Blast Radius

publication-exporter CLI surface (new command), admission package (contract projection reads EssayAdmission's rules), test fixtures shared between admission and contract tests. No effect on prepare/approve/release/site paths.

## Reversibility

high
