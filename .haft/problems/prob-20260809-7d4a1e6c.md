# G5 — make the macOS-native distribution boundary explicit

## Signal

The first real-plugin trial after S07 now works with a GraalVM native executable on this macOS Apple-Silicon machine, but the project has no recorded distribution contract. The Obsidian plugin needs a stable executable path and an operator needs to know which environments are supported. Without that boundary, a developer build under `target/` can be mistaken for a portable or automatically managed product distribution.

## Problem Type

synthesis

## Constraints

- macOS on Apple Silicon is the only supported runtime for the foreseeable future.
- Windows and Linux are explicitly outside scope, with no compatibility, packaging, installer, or support commitment.
- The Obsidian plugin invokes an operator-configured absolute executable path; it does not build, download, update, or discover the executable.
- The supported runtime is a GraalVM native executable; a JVM/JAR may remain a development and diagnostic path, not a second supported operator distribution.
- This decision must not introduce cross-platform packaging infrastructure, an updater, code signing/notarization work, or a new exporter feature.

## Acceptance

A DecisionRecord for G5 states that macOS Apple Silicon with a GraalVM native executable is the sole supported distribution boundary, defines the plugin's configured-path responsibility, and explicitly excludes Windows and Linux. The recorded contract gives a future operator one clear installation/configuration route and does not claim deployment, automatic updates, or support that the pilot has not demonstrated.

## Blast Radius

Distribution documentation, the plugin's executable-path setting and its operator instructions, plus future release/build scripts. The publication workflow, bridge schema, approved snapshots, and site output semantics are unaffected.
