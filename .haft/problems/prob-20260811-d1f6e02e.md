# S16 — Whole-vault discovery and aggregate admission (ADM-01, ADM-05)

## Signal

VaultReader.listPublishCandidates() (publication-exporter/src/main/java/dev/eugene/publicationexporter/vault/VaultReader.java) already discovers Boolean-publish=true notes and NoteIntake.admit(...) already validates one note end-to-end, and RefreshPublicationQueueHandler already iterates listPublishCandidates() per-note — but every existing aggregate consumer (refresh-publication-queue) silently treats an inadmissible note as EXCLUDED and moves on. No command exists that reports a note-scoped operation's real ADM-05 "whole-vault manifest" guarantee: that an aggregate operation either blocks or surfaces every invalid selected note's diagnostics, never silently omitting one from a manifest that looks complete. The real FilesystemVaultReader.listPublishCandidates() also has no proven ordering or ignored-path contract (Files.walk's traversal order is not guaranteed sorted, and there is no dedicated test proving a note inside a normally-git/tool-ignored path like a dotfolder is still discovered) — both are prerequisites for a whole-vault listing an authoring tool could trust.

## Constraints

- At most one new production boundary adapter this slice — the real discovery adapter is FilesystemVaultReader as it already exists, hardened with an ordering/ignored-path contract, not a wholly new class, unless acceptance-test evidence proves otherwise
- No queue-state mutation — this command must not write workflow status or any other persisted state
- No release of a partially valid vault — aggregate release itself is out of scope, only the discovery/admission manifest that a future release slice would consume
- In-memory acceptance subset stays well under the 1s slice budget

## Optimization Targets

- No selected note is ever silently dropped from an aggregate result — every invalid selected note's diagnostic is surfaced or the whole operation blocks
- Deterministic, reproducible whole-vault listing order

## Acceptance

A new read-only whole-vault command lists every Boolean-selected note exactly once, excludes publish-flag lookalikes (absent/false/string "true"), includes selected notes in normally-ignored vault paths, and — if any selected note fails admission — the command's result is not a manifest that silently omits that note: it is blocked or otherwise makes every failing note's diagnostics explicit, per ADM-05's "Whole-vault release is requested" scenario. The real discovery adapter has an explicit, tested ordering contract (deterministic, not incidental to filesystem traversal order) and an explicit, tested ignored-path contract (a selected note under a dotfolder or other normally-tool-ignored path is discovered). Queue-state mutation (refresh-publication-queue's job) and actually releasing a partially-valid vault remain out of scope.

## Blast Radius

publication-exporter CLI surface (one new read-only command), a new aggregate-discovery handler reusing NoteIntake/EssayAdmission, FilesystemVaultReader's listPublishCandidates() (ordering/ignored-path hardening only). No effect on prepare/approve/release/site/refresh-publication-queue command behaviour.

## Reversibility

high
