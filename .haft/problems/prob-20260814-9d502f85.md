# S18 — Direct-target source-ID admission (SEM-01 direct targets)

## Signal

Preparing a note with a direct private target does not yet evaluate the target's source ID at all: SEM-01 is only realized for the selected source note's own identity (S02's scope pin explicitly defers "the direct-private-target part of both scenarios" to S18). LinkResolver/PublicNoteIndex (S13, dec-20260810-cc3f02ed) resolve link targets for routing/labeling but never gate prepare on target source-ID validity, so a direct private target with a missing or duplicate source ID can still reach translation/candidate mutation today.

## Problem Profile

deep

## P2W Readiness

p2w_blocked

## Why Now

First slice of Milestone D (semantic publication frontier); S19 (stable occurrence maps) and S20 (late-bound activation) both depend on source identity being admissible for direct targets first, per the plan's deliberate ordering ("Semantic identity enters the simple path only where the active Haft decision requires it").

## Scope

One small in-memory vault identity index proves: preparing a note with a direct private target succeeds only when both the source and the target have unique, human-assigned source IDs; a missing or duplicate target identity returns metadata_blocked before job or candidate mutation, matching the existing SEM-01 scenario wording exactly. No path fallback or automatic identity allocation exists in either the fake or the production adapter — this is a closed admission gate, not a best-effort lookup. Occurrence IDs (SEM-02), references.json entries (SEM-03 non-empty map), and target link activation (SEM-04/05) are explicitly out of scope — those are S19/S20.

## Constraints

- Minimal-slice discipline per implementation-plan.md: 1-3 new OpenSpec scenarios, at most one new production boundary adapter, in-memory acceptance subset under 1 second, no foundation-only/refactor-only milestone.
- Reuse SEM-01's already-fully-specified requirement text; only touch specs/semantic-references/spec.md with a MODIFIED-Requirements delta if design finds a genuine wording gap, otherwise the delta is a scope-pins.md claim (S02 precedent for ADM-02).
- No path-derived or automatically-allocated identity in either the in-memory fake or the real adapter — missing/duplicate source ID fails closed as metadata_blocked.
- Must not implement occurrence IDs, references.json population, or late-bound activation incidentally; those remain S19/S20.
- Whole prior acceptance suite (802 tests as of baseline, 2026-08-14) must stay green throughout.

## Acceptance

An OpenSpec change (proposal, spec, design, tasks) documents the slice; one fixture with a direct private target completes prepare successfully only when source and target both carry unique human-assigned source IDs; a fixture with a missing or duplicate target source ID returns metadata_blocked before job or candidate mutation; write-publication-contract (if touched) reflects no incidental scope creep; the whole prior acceptance suite stays green; the final whole-branch review (Codex, gpt-5.6-sol, max effort) passes with no unresolved Important/Critical findings.

## Blast Radius

One in-memory vault identity index and its wiring into the existing prepare path (PrepareHandler / EssayAdmission-adjacent code). No changes expected to release, approval, or the S13 LinkResolver/PublicNoteIndex routing behavior — this slice only gates identity, it does not resolve or activate links.

## Reversibility

high — new admission-gate code additive ahead of the existing prepare path; revertible via git without touching prior slices' behavior
