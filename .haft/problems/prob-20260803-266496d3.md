# G1 — new exporter project identity

## Signal

S01 needs a concrete runtime, build tool, sibling directory name, and executable identity for &lt;new-exporter&gt; before any acceptance test can be wired; the plan forbids deciding this implicitly inside slice code.

## Constraints

- Must not collide with the exporter-java directory, which remains a compatibility oracle, not a code donor.
- Must be easy to compare/cross-check against exporter-java's Java/Maven toolchain.
- Naming should use existing project domain vocabulary (publication, not a version-numbered 'v2'/'next' name that rots).
- OS-level packaging/distribution strategy is explicitly out of scope here — deferred to G5.

## Optimization Targets

- Low setup friction for TDD/acceptance-test tooling
- Comparability against exporter-java as compatibility oracle

## Acceptance

A recorded decision states the runtime/language, build tool, sibling directory name, and executable/artifact name for the new exporter, consistent with the operator's Java/Maven choice.

## Blast Radius

New sibling directory scaffold only; no production behaviour yet.

## Reversibility

high
