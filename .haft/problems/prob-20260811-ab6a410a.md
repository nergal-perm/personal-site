# S17a — blog/note kind and the PublicationKind/PublicationKinds seam (ADM-03, ADM-04, PCM-02, PCM-06)

## Signal

The publication-exporter's admission and contract code is hardcoded to one kind. EssayAdmission (publication-exporter/src/main/java/dev/eugene/publicationexporter/admission/EssayAdmission.java) fixes REQUIRED_COLLECTION="blog"/REQUIRED_CONTENT_TYPE="essay" as class constants; NoteIntake.admit() (intake/NoteIntake.java) directly instantiates `new EssayAdmission()` with no kind-selection seam; EssayPublicationContract.kind() is a static single-kind factory that PublicationContractWriter.write() wraps in a hardcoded `List.of(EssayPublicationContract.kind())`. site/src/content.config.ts already defines a second real blog content type — blogNote (contentType:'note', sharing publicBaseFields/translationFields/editorialFields with blogEssay, plus optional observation/model/boundary/experiment fields, no required structured body) — that the exporter cannot yet admit, prepare, approve, or release, because every seam assumes essay is the only kind. Per openspec/implementation-plan.md's S17a entry and its 'Shared refactoring rule', this slice both proves blog/note through the already-working prepare→approve→release path and performs the first justified refactor: extracting an immutable PublicationKind role plus a PublicationKinds collection that NoteIntake, the contract writer, and (per the 'Kind-neutral lifecycle rule') future public-link indexing all share, replacing NoteIntake's hardcoded EssayAdmission.Result with an AdmittedPublication.

## Why Now

openspec/implementation-plan.md sequences S17a immediately after S16 (already closed, prob-20260811-d1f6e02e) as the start of the S17a–S17f content-kind ladder (Milestone C), and explicitly requires the PublicationKind/PublicationKinds extraction to happen inside this slice's red-green-refactor cycle rather than as a separate framework milestone.

## Scope

publication-pipeline

## Constraints

- At most one new production boundary adapter — none is expected; kind selection is pure in-process dispatch over an existing, already-proven prepare/approve/release path
- No generic schema/reflection framework, no speculative cross-kind inheritance — PublicationKind is a role each kind implements directly (essay and note), selected by (collection, contentType) key via PublicationKinds' deterministic lookup
- NoteIntake.admit() must return an AdmittedPublication, not a concrete kind result type, and take the same PublicationKinds instance the contract writer uses
- Do not generalize beyond what essay+note evidence requires — do not add fields, body-section machinery, or hooks for book/album/concept/editorial kinds this slice
- In-memory acceptance subset stays well under the 1s slice budget
- The existing blog/essay path (all prior slice acceptance tests) must keep passing unchanged after the refactor

## Optimization Targets

- blog/note completes the same prepare→approve→release path already proven for blog/essay, exercised through one new acceptance fixture
- Adding blog/note changes only an explicit kind-composition list, its own fixture, and genuinely new site-facing pieces — no new collection/type conditionals appear in NoteIntake, PrepareHandler, approval, or release code
- write-publication-contract's output includes a complete blog/note entry (required fields, no required body sections) alongside the unchanged blog/essay entry

## Acceptance

One blog/note fixture note (contentType 'note', all shared blogShared fields, no structured body required) is admitted, prepared into an RU+EN candidate pair, approved as an approved snapshot, and released into site output through the same handlers/CLI commands already proven for blog/essay — with no change to blog/essay's observable behaviour (its full existing acceptance suite stays green). Admission for both kinds routes through a shared PublicationKind role + PublicationKinds registry (deterministic (collection, contentType) lookup, unsupported-kind diagnostics, sorted contract enumeration) instead of EssayAdmission's hardcoded constants. NoteIntake.admit() returns an AdmittedPublication carrying whichever kind matched. write-publication-contract emits entries for both blog/essay and blog/note, each independently correct.

## Blast Radius

publication-exporter admission package (EssayAdmission's kind-specific logic becomes an EssayPublicationKind implementation; a new NotePublicationKind is added; PublicationKind role and PublicationKinds registry are new), intake/NoteIntake.java (returns AdmittedPublication), contract package (EssayPublicationContract folds into EssayPublicationKind's contract; PublicationContractWriter composes PublicationKinds instead of a hardcoded list), new acceptance/unit fixtures for blog/note. No change to PrepareHandler/ApprovedSnapshotWorkspace/release/site CLI wiring beyond consuming AdmittedPublication instead of EssayAdmission.Result; no new CLI command; no bridge schema-v2 change.
