# Slice S21 — Read-only legacy diagnosis

## Resolution

Addressed via `openspec/changes/archive/2026-08-18-s21-read-only-legacy-diagnosis/`. The implementation is in `publication-exporter`, not the historical `exporter-java` module: an explicitly invoked inventory command reports legacy state deterministically without mutating the workspace, while normal prepare, review, and release paths fail closed with migration-required evidence. The archived change records all completed tasks and final-review dispositions. Fresh verification on 2026-08-18 passed: `mvn -f publication-exporter/pom.xml test` — 959 tests, 0 failures, 0 errors, 0 skipped.

## Signal

Requirements MIG-01, MIG-02, MIG-05 (incomplete-state gate) are specified in openspec/specs/legacy-transition/spec.md but not yet implemented. There is currently no way to inventory a legacy workspace (old exporter-java pairs) against the new exporter's semantic-state model, and normal prepare/release commands do not yet fail closed with migration-required evidence when they encounter legacy-shaped state.

## Scope

publication-exporter: an explicitly invoked read-only migration inventory command/adapter and fail-closed guards on existing prepare/review/release paths when legacy-shaped state is detected. No decision draft generation, no apply, no catalog mutation, and no activation (those are S22/S23).

## Acceptance

An explicitly invoked migration inventory emits a deterministic report for a legacy workspace (in-memory legacy pairs and semantic-state markers first, then a real read-only inventory adapter with a no-mutation contract), while normal prepare/release fails closed with migration-required evidence and performs no mutation when it encounters legacy-shaped state. Requirements MIG-01, MIG-02, MIG-05 (incomplete-state gate) are satisfied. Decision draft generation, apply, catalog mutation, and activation remain explicitly excluded per the implementation plan.
