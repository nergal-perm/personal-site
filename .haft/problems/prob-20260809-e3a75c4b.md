# Configurable Codex or Antigravity translation engine

## Signal

`prepare` currently hard-wires `codex exec` through `CodexTranslationCommand`. The operator wants most notes translated by the installed Antigravity `agy` CLI while retaining a deliberate switch back to Codex, without rebuilding the macOS native executable or adding a new bridge argument. Both agents already own their own installed skills; the exporter only needs to select and invoke an engine inside its existing job workspace.

## Problem Type

synthesis

## Constraints

- Engine selection is read from configuration, not a publication-exporter CLI argument or Obsidian plugin setting.
- The persistent file is `<exporterRoot>/publication-exporter.toml`; the plugin already launches the executable with `exporterRoot` as its working directory.
- `PUBLICATION_EXPORTER_TRANSLATION_ENGINE` overrides the file for a temporary run.
- No silent engine fallback: malformed configuration, an unknown engine, or a failing/missing selected CLI produces the existing `translation_failed` result.
- Antigravity uses its own installed skills; no skill copying, syncing, or project-to-agent skill bridge is added.
- Retain the current TranslationWorker, isolated JobWorkspace, prompt, timeout, result-file names, bridge schema, and approval/release behavior.

## Acceptance

With `engine = "antigravity"` in the documented configuration file, `prepare` starts `agy` non-interactively in the existing job workspace and accepts the same three result files as the Codex path. With `engine = "codex"`, behavior remains the current Codex command. The environment variable wins for one run. Missing configuration defaults to Codex. Invalid selection is a schema-v2 `translation_failed` response and never invokes another engine. The root README documents setup, precedence, switching, and troubleshooting.

## Blast Radius

`publication-exporter` translation command selection/configuration and its tests; root README; a new Haft DecisionRecord. No plugin argv/settings, vault content, review snapshots, release/site output, or agent-skill installation.

## Reversibility

high
