# G2 — bridge schema v2 single source of truth

## Signal

The current exporter-java emits BridgeResponse.SCHEMA_VERSION = 3 while obsidian-plugin's bridge-client.js and main.js both hard-reject anything but schemaVersion === 2 — a live, verified drift. BRG-03 requires the contract be defined once and consumed by both sides' conformance tests; nothing currently plays that role.

## Constraints

- Must be consumable by both a Java test suite (publication-exporter) and a JS test suite (obsidian-plugin) without duplicating field/enum definitions in each language.
- Must express command names, required fields, field types, enum values, and v2 compatibility rules (unknown optional fields ignorable) per BRG-01/02/03.
- Must be versioned so a future major bump is an explicit, reviewable change, not silent drift.

## Optimization Targets

- Single-sourced contract enforceable by CI on both sides
- Directly closes the observed schemaVersion 3 vs 2 mismatch

## Acceptance

A recorded decision states the carrier format and repository location for the bridge schema v2 contract, and how exporter and plugin conformance tests each consume it.

## Blast Radius

A new small shared contract carrier plus two thin conformance-test wirings (Java + JS); no behavioural change to either existing side yet.

## Reversibility

high
