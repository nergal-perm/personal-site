## Why

SEM-02 already requires that every eligible semantic link occurrence get a stable occurrence ID, preserved source order, and identical encoding across RU, EN, and the reference map — but today that machinery does not exist. `LinkResolver` resolves and inlines public links directly into the rewritten body, then forgets them; the only per-occurrence memory it keeps is an unordered, deduplicated `Set<String>` of private target stems (used solely by S18's identity check), which cannot carry order, target identity, or a stable ID. `ReferenceMap.occurrences()` is a placeholder that always returns an empty `List<Object>`, locked in by three existing tests (`ReferenceMapTest`, `ReferenceMapCodecTest`, and `PrepareHandlerTest`'s `validEssayInstallsOneCandidateAndReturnsReadyForReview`). `TranslationJob` and `EnglishTranslation` carry no occurrence-shaped data at all, so a translation worker today has no channel to receive or return occurrence identity — TRP-05's "translation reorders or invents occurrences" scenario has nothing to check yet. S18 closed source-identity admission for direct private targets but explicitly deferred occurrence IDs and `references.json` population to this slice.

## What Changes

- Give link occurrences a first-class, ordered identity as `LinkResolver` resolves the body: instead of discarding per-occurrence data (public links inlined-and-forgotten, private stems collapsed into an unordered `Set`), resolution reports an ordered sequence of occurrences, one per eligible wikilink, each carrying its source order index, target stem/source ID, and rendered label — public and private targets alike, since SEM-04/SEM-05 (release-time late-bound activation, S20) require every occurrence's identity to survive independently of whether its target is currently public or private.
- Assign each occurrence a stable ID: reuse the prior candidate's occurrence ID when an occurrence's identity still matches (SEM-02's "occurrences are unchanged" scenario), using `CandidateWorkspace.read(identity)` (already returns the prior `CandidateSnapshot`, which already embeds `referenceMap`) as the source of the previous map. Transclusions, protected-code tokens, malformed links, and non-semantic constructs remain ineligible, matching `LinkResolver`'s and `MarkdownProtectedRegions`' existing exclusions.
- Preserve occurrence identity through translation without widening the translation contract: after `translationWorker.translate(...)` returns the English body, re-resolve *its* links through the same widened `LinkResolver` pass (a fresh, unassigned target-identity sequence — no reuse-matching applied to this pass) and compare that sequence to RU's assigned occurrence sequence positionally. `TranslationJob`, `EnglishTranslation`, `TranslationWorker`, and every Null/fake implementation and existing test call site stay untouched; a conforming worker satisfies TRP-05 by preserving the same links in its translated prose, not by populating a new data field.
- Validate before installation, not after: on a match, EN's occurrences inherit RU's occurrence IDs positionally; on any divergence (different target, order, or count), reject before `installCandidate` writes anything (TRP-05's second scenario) — matching this codebase's existing "block before mutation" discipline (`EnglishCandidateValidator`, `DirectTargetIdentityCheck`).
- Replace `ReferenceMap`'s stubbed `occurrences()` with a real, codec-round-tripped list bound to the candidate's exact RU/EN hashes, occurrence order, target source IDs, source paths, and localized labels (SEM-03's non-empty-map scenario) — validated by the codec against duplicate keys, unsafe paths, wrong hashes, reordered/unknown/unused IDs (SEM-03's "inconsistent" scenario), with unit tests at the codec level for the genuinely combinatorial parsing cases (duplicate keys, hash stability, strict number/order parsing), per this project's outside-in discipline.
- Explicitly excluded: resolving an occurrence into a public route at release time, and any change to what gets rendered when a target's approval state changes — both remain S20's late-bound target activation. This slice only makes occurrence identity exist and survive prepare; it does not change release behavior.

## Capabilities

### New Capabilities

(none — SEM-02, SEM-03, and TRP-05 are already fully specified in the baseline; see scope-pins.md for what remains scoped versus deferred)

### Modified Capabilities

- `semantic-references`: SEM-02 (occurrence assignment and order) and SEM-03's non-empty-map scenario are realized for the first time. Whether this needs a `MODIFIED Requirements` wording delta or only a `scope-pins.md` claim — and precisely what counts as an "eligible semantic link occurrence" for this slice's minimal one-referrer/one-target acceptance boundary (public targets, private targets, or both) — is decided during the collaborative-design pass on spec.md, not assumed here.
- `translation-preparation`: TRP-05 (preserve semantic occurrence identity through preparation) is realized for the first time.

## Impact

- New code: an `Occurrence` value type (id, order index, target source ID, RU/EN labels — see scope-pins.md for the exact field set) threaded from `LinkResolver`'s widened result through `ReferenceMap`; a small occurrence-ID assignment step that consults the prior candidate's reference map for positional reuse; a comparison step that re-resolves the translated EN body's own occurrences and validates them against RU's before candidate installation.
- Existing types widened, no new production boundary adapter and zero translation-contract changes: `LinkResolver`/`LinkResolutionOutcome` (report ordered occurrences instead of/alongside the current unordered stem set) and `ReferenceMap`/`ReferenceMapCodec` (real occurrence read/write instead of the always-empty stub). `TranslationJob`, `EnglishTranslation`, and `TranslationWorker` are untouched. This mirrors S18's precedent of widening existing in-process types rather than introducing a port — this slice's acceptance boundary is explicitly in-memory (one referrer, one target, a previous map fixture).
- Existing tests that assert the empty-occurrence stub (`ReferenceMapTest.occurrencesIsAlwaysEmpty`, `ReferenceMapCodecTest`'s empty-occurrences round-trip, `PrepareHandlerTest`'s `validEssayInstallsOneCandidateAndReturnsReadyForReview`) will need deliberate updates — the no-link case must still produce an empty (not absent) occurrence list; only the link-bearing case changes.
- No changes expected to release, site, or approval behavior in this slice — occurrence identity is produced and validated at prepare time only; consuming it at release is S20.
